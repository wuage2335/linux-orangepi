# RK3588 OV13850 RKAIQ/3A Image Quality Design

## Goal

在不破坏阶段0-5稳定链路的前提下，为Orange Pi 5 Pro上的OV13850学习驱动接入
Rockchip RKAIQ 3A，使RKISP输出具备自动曝光和自动白平衡，并形成可回滚、可量化、
可复现的图像质量验证流程。

## Current Evidence

- RKISP输出1920x1080 NV12@30，采集、MPP、RTP和RTSP已稳定；
- sensor controls固定为exposure 1536/1648、analogue gain 16/248；
- 画面在本地RKISP阶段已经偏暗偏绿，网络和decoder不是根因；
- `/etc/iqfiles/ov13850_CMK-CT0116_default.json`存在，分辨率2112x1568；
- DT命名为module `CMK-CT0116`、lens `default`，与IQ文件名完全匹配；
- 系统没有`rkaiq_3A_server`、`librkaiq.so`、服务或apt包；
- 正式`ov13850.c`有module-info ioctl，学习驱动尚未实现；
- 固定RK3588 RKAIQ源码为commit
  `5af997da2442a504b1005cb804a75745171dc522`，ISP_HW_V30；
- 该旧用户态头文件与当前6.1 UAPI的`rkmodule_inf`大小不同，不能直接使用旧ABI。

## Options

### A. Current-kernel ABI + private RKAIQ bundle (selected)

按正式驱动模式补module-info；以固定RK3588源码构建3A server和librkaiq，但编译时
使用当前内核UAPI。产物放项目私有bundle，通过`LD_LIBRARY_PATH`运行。

优点：能同时实现AE/AWB/CCM/Gamma，保留当前内核和回滚路径。缺点：构建复杂，
需要严格验证kernel/userspace ABI。

### B. Manual exposure/gain only

通过V4L2 controls做明暗A/B。风险最低，但只能提亮，不能可靠修复AWB偏绿。仅作为
基线和RKAIQ失败时的诊断工具，不作为最终结果。

### C. Replace vendor image/kernel

使用自带RKAIQ的完整厂商镜像。会破坏当前学习内核、驱动和阶段证据，因此排除。

## Architecture

```text
DT module metadata
  -> ov13850_i2c_min RKMODULE_GET_MODULE_INFO
  -> RKAIQ media discovery
  -> private rkaiq_3A_server + private librkaiq.so
  -> /etc/iqfiles/ov13850_CMK-CT0116_default.json
  -> AE/AWB writes sensor controls and ISP params/stats
  -> RKISP mainpath NV12 -> existing MPP/RTP/RTSP
```

### Driver boundary

学习驱动新增module index/facing/name/lens字段，从现有DT属性读取。实现
`RKMODULE_GET_MODULE_INFO`、compat copy和core ops；sensor名称固定为`ov13850`，
subdev entity改为Rockchip常用的`m%02d_%c_ov13850 <i2c-dev>`格式。正式驱动不修改。

### Runtime boundary

RKAIQ源码、构建目录和bundle不直接提交720MB上游源码。项目只保存：固定来源、
SHA、构建/打包脚本、必要的ABI同步步骤、最小运行脚本和验证脚本。bundle为生成物，
不覆盖系统`/usr/lib`；首次运行不创建systemd服务。

### ABI rule

RKAIQ必须使用当前仓库`include/uapi/linux/rk-camera-module.h`编译，确保
`RKMODULE_GET_MODULE_INFO` ioctl号和payload大小与内核一致。构建后用小型probe
程序直接对sensor subdev调用ioctl并验证sensor/module/lens三个字符串，再启动3A。

## Safety And Rollback

1. 不重启、不替换Image/DTB/uInitrd；
2. 不覆盖系统库、可执行文件或IQ JSON；
3. 3A进程使用项目bundle，可通过进程终止完全回滚；
4. 部署新内建驱动前保留当前Image和回滚入口；若只构建未部署，不改变板端；
5. 任何SIGSEGV、ABI错误、stream失败或fault都停止3A并恢复基线；
6. 手动controls测试结束恢复默认exposure/gain。

## Validation

### Static and build

- module-info单元/源码契约检查先失败后通过；
- 同一`O=`内核输出目录构建Image；
- RKAIQ固定commit、aarch64架构、动态依赖和origin SHA验证；
- module-info probe返回`ov13850/CMK-CT0116/default`。

### Functional

- 3A server发现`ov13850_i2c_min 3-0010`并加载匹配IQ文件；
- 开流后exposure或gain会随明暗变化，证明AE闭环；
- 中性灰/白场的UV均值更接近128且R/B色偏降低，证明AWB/CCM生效；
- 明亮、普通、较暗三种场景均可采集有效NV12；
- 3A退出后sensor PM为suspended/0，无CSI/ISP/MMU/IOMMU fault。

### Regression

- 1920x1080 NV12@30持续采集；
- MPP DMA-BUF编码和RTSP播放不因3A接入失效；
- 记录3A进程CPU/RSS和端到端新增延迟；
- 如果完整3A无法在当前ABI上运行，保留module-info、构建审计和手动亮度基线，明确
  阻塞点，不伪称AWB完成。

## Deliverables

- module-info驱动补丁及测试；
- 私有RKAIQ构建、bundle、运行和验证脚本；
- 修复前后NV12统计、controls、日志和截图；
