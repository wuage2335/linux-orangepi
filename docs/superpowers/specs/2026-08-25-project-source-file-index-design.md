# Project Source File Index Design

日期：2026-08-25

## 目标

为 Orange Pi 5 Pro + OV13850 摄像头学习项目建立一份面向学习的源码索引，让使用者
能够快速回答三个问题：项目改了哪些源码、每个文件负责什么、应该沿什么依赖关系阅读。

## 统计范围

纳入：

- 项目新增或修改的内核 C 源码、Kconfig 和 Makefile；
- 设备树源码与 overlay 源码；
- ISP、RGA、MPP 的 C/C++ 源码；
- 直接参与构建、配置、打包和验收的 Makefile 与 Shell 测试脚本；
- 为理解源码提供设计边界、实施顺序和验证结果的项目文档。

排除：

- Image、DTB、DTBO、KO、NV12、H.264/H.265 和压缩包等生成物；
- `build/`、`release/`、`staging/` 中的构建或部署产物；
- 官方 librga 的每个头文件明细。第三方接口只按目录汇总并记录版本来源；
- Linux 内核原有且本项目未修改的普通源码。

## 文档结构

索引保存为 `docs/codex/project_source_file_index.md`，按以下子系统排列：

1. 内核学习驱动与 Kbuild/Kconfig；
2. CAM2 设备树与 overlay；
3. RKISP 配置；
4. RGA 图像处理；
5. MPP 硬件编码；
6. 直接相关的设计、计划和验证文档。

每个条目记录：路径、变更性质、所属阶段、文件作用、学习重点和主要依赖关系。
同一用途的一组重复文件允许汇总，但项目自行编写的源文件和脚本必须逐项列出。

## 取证方式

- 以当前 `main` 的 Git 历史、文件状态和项目目录为事实来源；
- 使用 `git log --name-status` 区分新增与修改；
- 使用源码内容确认职责，不仅依据文件名猜测；
- 文档完成后检查所有索引路径真实存在，并检查 Markdown 相对链接。

## 维护规则

- 新阶段新增或修改源文件时，同一提交或阶段收口提交同步更新索引；
- 文件删除或改名时更新原条目，不保留失效路径；
- 生成物只在对应构建脚本条目中说明，不进入逐文件索引；
- 索引是学习导航，不替代 HANDOFF、task plan 或 validation 文档。
